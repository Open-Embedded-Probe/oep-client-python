# 仕様追従で見つけた実装上の負担

実装を oep-spec に追従させるときに、実装がかなり不便だと分かった仕様の規則を記録する。仕様の見直しの材料であり、規範ではない。
仕様に入ったもの、取り下げたものは消し、今開いているものだけを置く。単に作業量が多いだけのもの、実装側の設計で解消できるものは載せない。

| # | 条項 | 不便な点 | 影響 | 代案 |
|---|---|---|---|---|
| 1 | core §2.3（後に来た同じ tag も検証の対象） | 要求の中で、繰り返さない既知の tag が 2 回来たとき、使わない 2 つ目以降の値まで、値域と対応の有無を op ごとに検証しなければならない。共通の TLV 読み取りは長さしか見られないので、検証を副作用のある処理から分け、同じ検証をすべてのコピーへ当てる作りが要る | probe（各 op）、仮想ベンチ | 要求の中の、繰り返さない既知の tag の重複を malformed にする（critical の bit を除いた番号で判定する。繰り返す tag と未知の tag は対象外）。今は有効な重複を新たに断る変更になる |
| 2 | core §2.2 / §2.3（応答・出来事・データの読み手の規則） | 送る側に「繰り返さない tag を応答で 2 度送らない」の義務が無いので、host は応答の TLV を読むすべての所で、最初のコピーを使い、長さの違う値を壊れたものとして扱う防御を持つ。Python は `catalog.first_value` / `first_fixed` に集めた | host、検査器 | probe は、応答・出来事・データで、繰り返さない tag を 2 度送らないと定め、検査器で確かめる。読み手の規則は変えない（要求の側の #1 とは別に書く） |
| 3 | console §2、core §9（stream はセッションのもので、セッションの終わりで解放する） | 1 回の実行ごとにセッションを開いて閉じる host（`oep` の各コマンド、試験のプロセス）は、コマンドの間に target が出した出力（起動直後の行など）を拾えない。console の素通し（core §13 の項目）は、セッションの無い間の出力をシリアルの口へ流すが、次のセッションで読み返すことはできない | host（CLI、試験） | セッションの無い間も受け続け、次のセッションで読める「保持の stream」を任意の機能として定める。閉じた stream の番号を使い回さない規則（core §9）とは別の資源にする |
